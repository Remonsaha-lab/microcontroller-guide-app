CHAPTER 1

Overview & Computer Architecture Fundamentals

1.1 Microcontroller Definition & Processing Engine Spectrum

A Microcontroller is a self-contained, monolithic computer-on-a-chip. Etymologically, it combines two concepts:

  • Micro: Refers to its sub-millimeter physical integration scale on a single silicon die.
  • Controller: A digital processing unit operating at the bit level to regulate an external physical process. A process is defined as a series of sequential or concurrent tasks designed to produce specific real-world outputs from physical inputs.

The Evolution of Digital Processing Engines:

  1. General-Purpose Microprocessor (MPU): Contains only the central processing unit (ALU, Register File, Program Counter, Instruction Decoder, Control Unit) on silicon. Memory (RAM, ROM) and peripheral subsystems (timers, I/O ports, serial links) must be externally interfaced across a printed circuit board using a wide parallel system bus. Examples: Intel Core i7, AMD Ryzen.
  2. Bit-Slice Processor: Modular ALU/register slices (e.g. 4-bit Am2901) cascaded in parallel to form custom-word-length computing engines.
  3. Digital Signal Processor (DSP): Specialized Harvard engine equipped with hardware Multiply-Accumulate (MAC) units, circular buffers, and barrel shifters designed for real-time Fourier transforms and digital filtering.
  4. Microcontroller (MCU): Integrates CPU, Non-Volatile Program Memory (Flash), Volatile Data Memory (SRAM), Non-Volatile Parameter Memory (EEPROM), Timers/Counters, ADC, and I/O ports on a single monolithic silicon substrate.

1.2 System Bus Organization & Total Memory Capacity Sizing

The CPU core communicates with on-chip memory and peripheral units through three distinct buses:

  • Address Bus (Unidirectional): Carries the binary address driven exclusively by the CPU to locate specific memory cells or I/O registers. For an address bus of width $m$ bits ($A_0\text{--}A_{m-1}$), the number of addressable locations is exactly $2^m$.
  • Data Bus (Bidirectional): Carries data words of width $n$ bits ($D_0\text{--}D_{n-1}$) transferred between CPU, memory, and peripherals during read and write cycles.
  • Control Bus: Carries command strobes ($\overline{RD}, \overline{WR}$), clocks, reset pulses, and acknowledgments.
$$\text{Total Addressable Memory Capacity} = 2^m \times n \text{ bits} = \frac{2^m \times n}{8} \text{ bytes}$$
// Example: A 16-bit address bus ($m=16$) with 8-bit data bus ($n=8$) can address $2^{16} \times 8 = 65,536\text{ bytes} = 64\text{ KB}$.

1.3 Memory Taxonomy: Non-Volatile vs. Volatile

Non-Volatile Memories (Retain data without power):
  • Mask ROM: Bit patterns hardwired during wafer mask fabrication; zero programmability, cheapest in volumes $>100\text{k}$.
  • PROM (One-Time Programmable): Built with nichrome/polysilicon fusible links; unprogrammed bits are '1', high-current pulses vaporize fuses to permanently write '0'.
  • UV-EPROM (FAMOS): Floating-gate avalanche MOS cells; programmed via hot-electron injection ($V_{PP} \approx 12.5\text{--}21\text{ V}$), erased by exposing the quartz window to $253.7\text{ nm}$ UV light for 15–20 minutes.
  • EEPROM: Electrically erasable byte-by-byte via Fowler-Nordheim tunneling through thin oxide ($<100\,\text{Å}$). Supports $\approx 100,000$ write cycles.
  • Flash Memory: Combines EEPROM electrical erasability with single-transistor EPROM density; erased in whole blocks/sectors. Standard storage for AVR firmware.
Volatile Memories (Lose contents upon power-down):
  • Static RAM (SRAM): Cell consists of a 6-transistor (6T) CMOS cross-coupled inverter bistable latch. Fast access time ($5\text{--}15\text{ ns}$), zero refresh overhead, draws static leakage power. Used for working data, call stacks, and heaps in ATmega2560 (8 KB).
  • Dynamic RAM (DRAM): Stores each bit as charge on a microscopic trench capacitor gated by 1 pass transistor (1T-1C cell). Massive density, but charge leaks within milliseconds, requiring continuous periodic refresh cycles.
  • Non-Volatile RAM (NV-RAM): Low-power SRAM integrated with an on-chip miniature lithium battery and power supervisory circuit that automatically switches to battery when $V_{CC}$ drops below $4.5\text{ V}$.

1.4 Harvard vs. Von Neumann Architecture & RISC vs. CISC

Von Neumann (Princeton) Architecture uses a single shared system bus for both instructions and data variables. Consequently, an instruction fetch and a data read/write cannot occur concurrently—a bottleneck known as the Von Neumann Bottleneck.

Harvard Architecture (AVR ATmega2560) features physically separate memory spaces and independent buses for Program Flash and Data SRAM. This enables concurrent single-cycle instruction pipelining: while the CPU is executing the current instruction on data registers, the next instruction is prefetched simultaneously over the dedicated program memory bus!

Watchdog Timer (WDT) & Sleep Modes

1. Watchdog Timer (WDT) Architecture & Operating Principles

The ATmega2560 Watchdog Timer (WDT) is a hardware supervisory safety peripheral designed to automatically detect and recover from software hangs, runaway execution, deadlock states, infinite loops, and severe electrical interference (EMI / voltage transients). Crucially, the WDT is driven by an independent, on-chip 128 kHz Low-Power RC Oscillator ($f_{WDT} \approx 128\text{ kHz}$ at $V_{CC} = 5.0\text{ V}$). Because this oscillator is physically separate from the CPU core clock ($clk_{CPU}$), prescalers, and external crystal oscillators ($16\text{ MHz}$), the Watchdog continues operating autonomously even if the primary system clock fails, crashes, or is completely stopped during low-power sleep modes.

Three Operating Modes of the ATmega2560 Watchdog Timer:
  • System Reset Mode: Traditional fail-safe watchdog operation. If the firmware fails to execute the wdt_reset() instruction before the programmed timeout counter elapses, the WDT forces an internal hardware reset pulse, pulling the CPU out of its locked condition. Hardware latches the Watchdog Reset Flag (WDRF) in the MCU Status Register (MCUSR).
  • Interrupt Mode: On timeout, the WDT asserts an interrupt request (vector WDT_vect) instead of resetting the MCU. This transforms the Watchdog into an ultra-low-power interval timer capable of waking the MCU from deep sleep modes (e.g., Power-down) without running power-hungry peripheral timers.
  • Interrupt and System Reset Mode (Dual Mode): The first timeout triggers the WDT_vect interrupt, allowing emergency telemetry logging, actuator safe-parking, or critical state backup to EEPROM. In the ISR, hardware automatically clears WDIE. If the system fails to resolve the fault and does not service the WDT before the second timeout period expires, a full hardware System Reset is executed.

  • WDIF (Bit 7 — Watchdog Interrupt Flag): Set by hardware when a timeout occurs with the WDT configured in Interrupt Mode. Automatically cleared when the CPU vectors to the WDT_vect ISR, or manually cleared by writing a logical '1' to it.
  • WDIE (Bit 6 — Watchdog Interrupt Enable): Enables Watchdog interrupts when set to '1' and the global interrupt enable bit ($I$-bit in SREG) is set. If WDE = 0, WDT operates in pure Interrupt Mode. If WDE = 1, WDT operates in Dual (Interrupt + Reset) Mode.
  • WDP3 (Bit 5 — Watchdog Prescaler Bit 3): Together with bits WDP2:0, determines the division factor of the $128\text{ kHz}$ clock, extending timeout periods from $16\text{ ms}$ up to $8.0\text{ s}$.
  • WDCE (Bit 4 — Watchdog Change Enable): Hardware safety lockout bit. Must be set to '1' whenever WDE is cleared or when altering prescaler bits WDP3:0. Once set, hardware automatically clears WDCE after exactly 4 clock cycles.
  • WDE (Bit 3 — Watchdog System Reset Enable): When set to '1', enables System Reset Mode upon timeout. Can only be cleared by writing a '0' within 4 clock cycles after asserting WDCE. If the non-volatile hardware fuse WDTON is programmed (0), WDE is hardwired to '1' and cannot be cleared by software.
  • WDP2:0 (Bits 2:0 — Watchdog Prescaler Bits 2, 1, 0): Low-order 3 bits of the 4-bit prescaler divider ($WDP3, WDP2, WDP1, WDP0$).

Mandatory Timed Sequence for Changing WDT Settings:

To prevent unintended tampering or accidental disabling of the Watchdog due to rogue pointers or runaway software, changing WDE or the prescaler bits requires a hardware-enforced two-step atomic sequence:

  1. Clear Watchdog Reset Flag (MCUSR): The reset flag WDRF must be cleared to '0' via MCUSR &= ~(1 << WDRF). If WDRF remains '1', hardware locks WDE in the enabled state, preventing software from modifying or disabling it.
  2. Disable Interrupts (cli()): Prevents an ISR from breaking the strict 4-cycle timing window between the unlock step and register update.
  3. Unlock Safety Interlock: Simultaneously write a logical '1' to both WDCE and WDE in WDTCSR in a single instruction: WDTCSR |= (1 << WDCE) | (1 << WDE);. Even if WDE is already 1, a 1 must be written to it.
  4. Write New Configuration Within 4 Cycles: Within the next 4 CPU clock cycles, write the desired values to WDE and WDP3:0 while writing a '0' to WDCE: WDTCSR = (1 << WDE) | (1 << WDP2) | (1 << WDP1) | (1 << WDP0);.
  5. Restore Interrupts (sei()): Re-enable global interrupts once the critical timed sequence completes.

2. Code Implementation: WDT in System Reset Mode (2.0s Timeout)

This bare-metal implementation configures the Watchdog in System Reset Mode with a 2.0-second timeout ($WDP3:0 = 0111_2$). It features early MCUSR flag clearance in the .init3 startup section to prevent infinite reset loops, periodic wdt_reset() servicing during normal operation, and a simulated software lockup demonstrating fail-safe hardware recovery.

#define F_CPU 16000000UL #include <avr/io.h> #include <avr/wdt.h> #include <avr/interrupt.h> #include <util/delay.h> // Startup Hook (.init3): Executes BEFORE main() and global C runtime constructors. // Essential on ATmega2560: After a Watchdog Reset, WDT remains enabled with the // shortest timeout (~16ms). If MCUSR is not cleared immediately, an infinite bootloop occurs! void wdt_early_init(void) __attribute__((naked)) __attribute__((section(".init3"))); void wdt_early_init(void) { MCUSR = 0; // Clear all reset source flags (PORF, EXTRF, BORF, WDRF) wdt_disable(); // Stop Watchdog during startup initialization } // Bare-metal function executing the 4-clock timed sequence for 2.0s System Reset void wdt_system_reset_init_2s(void) { cli(); // Disable interrupts to protect 4-cycle execution window wdt_reset(); // Reset internal WDT counter MCUSR &= ~(1 << WDRF); // Clear WDRF (WDE cannot be cleared if WDRF is set) // Step 1: Timed sequence unlock - set WDCE and WDE simultaneously WDTCSR |= (1 << WDCE) | (1 << WDE); // Step 2: Within 4 clock cycles, set WDE=1 and WDP3:0 = 0111 (2.0s timeout) WDTCSR = (1 << WDE) | (1 << WDP2) | (1 << WDP1) | (1 << WDP0); sei(); // Re-enable interrupts } int main(void) { // Configure PB7 (Arduino Mega onboard LED / Pin 13) as OUTPUT DDRB |= (1 << DDB7); // Flash LED 3 times quickly to signify a fresh system boot or reset recovery for (uint8_t i = 0; i < 3; i++) { PORTB |= (1 << PORTB7); _delay_ms(80); PORTB &= ~(1 << PORTB7); _delay_ms(80); } // Arm Watchdog Timer in System Reset Mode with 2.0s timeout wdt_system_reset_init_2s(); // (avr-libc equivalent: wdt_enable(WDTO_2S);) uint16_t iteration = 0; while (1) { // Toggle PB7 LED (Heartbeat indication) PORTB ^= (1 << PORTB7); _delay_ms(500); // Service the Watchdog Timer ("Pat/Kick the Dog") // Clears the internal prescaler before the 2.0-second limit expires wdt_reset(); iteration++; // Simulate a software deadlock / infinite blocking condition after 10 loops (5s) if (iteration >= 10) { // Unrecoverable fault simulation: entering infinite loop WITHOUT wdt_reset() while (1) { // CPU is stuck here; Watchdog counter reaches 2.0s -> HARDWARE RESET! } } } return 0; }

3. Code Implementation: WDT in Interrupt Mode for Periodic Wake-Up

By configuring WDIE = 1 and WDE = 0, the WDT serves as an autonomous interval timer that executes an ISR rather than resetting the MCU. In this example, the CPU sleeps in deep Power-down mode ($\approx 4.5\ \mu\text{A}$), wakes up every 2.0 seconds via WDT_vect, toggles an indicator LED, and returns to sleep.

#define F_CPU 16000000UL #include <avr/io.h> #include <avr/interrupt.h> #include <avr/wdt.h> #include <avr/sleep.h> volatile uint32_t wdt_tick_count = 0; volatile uint8_t wdt_woke_flag = 0; // Watchdog Interrupt Vector: Executes every 2.0 seconds upon WDT timeout ISR(WDT_vect) { wdt_tick_count++; wdt_woke_flag = 1; // Set wake flag for background processing in main loop // Note: In pure Interrupt Mode (WDIE=1, WDE=0), hardware keeps WDIE set! } // Configure WDT for periodic interrupt generation (2.0s interval) void wdt_interrupt_init_2s(void) { cli(); wdt_reset(); MCUSR &= ~(1 << WDRF); // Timed sequence: unlock WDTCSR WDTCSR |= (1 << WDCE) | (1 << WDE); // Configure: WDIE=1 (Interrupt Enable), WDE=0 (No Reset), Timeout=2.0s (0111b) WDTCSR = (1 << WDIE) | (1 << WDP2) | (1 << WDP1) | (1 << WDP0); sei(); } int main(void) { // Configure PB7 (Pin 13 LED) as OUTPUT DDRB |= (1 << DDB7); PORTB &= ~(1 << PORTB7); // LED off // Initialize WDT in pure Interrupt Mode wdt_interrupt_init_2s(); // Select deepest power-saving state: Power-down Mode set_sleep_mode(SLEEP_MODE_PWR_DOWN); while (1) { // Arm Sleep Enable (SE) bit sleep_enable(); // Atomically enable interrupts and sleep sei(); sleep_cpu(); // ========================================================= // CPU SLEEPS HERE (Consuming only ~4.5 uA with WDT active) // Timeout expires -> ISR(WDT_vect) executes -> Resumes here // ========================================================= // Disarm Sleep Enable bit immediately upon waking for safety sleep_disable(); // Handle scheduled wake-up task if (wdt_woke_flag) { wdt_woke_flag = 0; // Toggle LED to signal periodic wake-up event PORTB ^= (1 << PORTB7); // [Perform quick sensor acquisition or wireless packet telemetry here] } } return 0; }

5. Sleep Mode Control Register (SMCR — Address: 0x53)

The SMCR register configures which low-power sleep mode will be entered when the CPU executes the SLEEP assembly instruction, and provides a crucial hardware interlock via the Sleep Enable (SE) bit.

  • Bits 7:4 — Reserved: Read-only bits that consistently return 0.
  • SM2:0 (Bits 3:1 — Sleep Mode Select Bits 2, 1, 0): Selects the target low-power state: 000 = Idle, 001 = ADC Noise Reduction, 010 = Power-down, 011 = Power-save, 110 = Standby, and 111 = Extended Standby (combinations 100 and 101 are reserved).

    Defensive Programming Practice: Keep SE = 0 throughout normal execution. Set SE = 1 immediately before the SLEEP instruction and clear SE = 0 immediately upon awakening to prevent erroneous sleep entry if rogue code branches to an arbitrary address.

6. Code Implementation: Low-Power Sensor Node Using sleep_mode() Macro

The standard <avr/sleep.h> library encapsulates AVR power management. The high-level sleep_mode() macro executes the atomic three-step sequence: sleep_enable() ➔ sleep_cpu() ➔ sleep_disable(). This complete example places the ATmega2560 into deep Power-down sleep and wakes up via an external push-button interrupt on pin PD0 (External Interrupt INT0 / Arduino Mega Pin 21). #include <avr/io.h>
#include <stdint.h>

/* SPI Pin Definitions for ATmega2560 on PORTB */
#define SPI_DDR   DDRB
#define SPI_PORT  PORTB
#define PIN_SS    PB0  /* Pin 19 */
#define PIN_SCK   PB1  /* Pin 20 */
#define PIN_MOSI  PB2  /* Pin 21 */
#define PIN_MISO  PB3  /* Pin 22 */

/**
 * @brief Initialize ATmega2560 SPI Controller as Master:
 *        - Mode 0 (CPOL=0, CPHA=0)
 *        - MSB first (DORD=0)
 *        - Clock = f_osc / 16 (1 MHz @ 16 MHz F_CPU)
 */
void SPI_MasterInit(void) {
    /* 1. Configure MOSI, SCK, and /SS as Outputs; MISO as Input */
    SPI_DDR |= (1 << PIN_MOSI) | (1 << PIN_SCK) | (1 << PIN_SS);
    SPI_DDR &= ~(1 << PIN_MISO);

    /* 2. Set /SS High to prevent accidental Slave Mode drop */
    SPI_PORT |= (1 << PIN_SS);

    /* 3. Configure SPCR:
          - SPE  = 1 (Enable SPI)
          - MSTR = 1 (Master Mode)
          - SPR0 = 1 (f_osc / 16 clock divider)
          - CPOL = 0, CPHA = 0 (Mode 0)
          - DORD = 0 (MSB first) */
    SPCR = (1 << SPE) | (1 << MSTR) | (1 << SPR0);

    /* 4. Clear Double Speed (SPI2X = 0) */
    SPSR &= ~(1 << SPI2X);
}

/**
 * @brief Transmit and simultaneously receive a single byte over SPI.
 * @param tx_data Byte to transmit out through MOSI.
 * @return uint8_t Byte shifted in through MISO from the slave.
 */
uint8_t SPI_MasterTransfer(uint8_t tx_data) {
    /* Start transmission by loading data into the Data Register */
    SPDR = tx_data;

    /* Wait for transmission to complete (SPIF set in SPSR) */
    while (!(SPSR & (1 << SPIF))) {
        /* Busy wait for hardware shift register */
    }

    /* Return the received byte from the SPDR buffer */
    return SPDR;
}

2 Two-Wire Serial Interface (TWI / I²C) Protocol

Multi-Master Open-Drain

The ATmega2560 Two-Wire Serial Interface (TWI) is 100% electrically and logically compatible with the Philips/NXP I²C standard. It uses two bidirectional open-collector/open-drain lines pulled up to $V_{CC}$ via external resistors (typically $2.2\,\text{k}\Omega$ to $4.7\,\text{k}\Omega$): SDA (PD1, Pin 44) for serial data and SCL (PD0, Pin 43) for serial clock.

SCL Clock Frequency & TWBR Register Calculation

Register: TWBR (0xB8)

The SCL frequency in Master mode is generated by dividing the ATmega2560 CPU clock using the 8-bit TWBR (TWI Bit Rate Register) and the 2-bit prescaler TWPS1:0 in TWSR:

SCL_freq = CPU_freq / (16 + 2 × TWBR × Prescaler)
Standard Mode (100 kHz) @ 16 MHz:
Prescaler = 1 (TWPS = 00)
100,000 = 16,000,000 / (16 + 2 × TWBR × 1)
⇒ TWBR = ((16,000,000 / 100,000) - 16) / 2 = 72
Fast Mode (400 kHz) @ 16 MHz:
Prescaler = 1 (TWPS = 00)
400,000 = 16,000,000 / (16 + 2 × TWBR × 1)
⇒ TWBR = ((16,000,000 / 400,000) - 16) / 2 = 12

* Note: The ATmega2560 hardware datasheet stipulates that TWBR must be 10 or higher in Master mode for stable operation.

twi_master.c 
#include <avr/io.h>
#include <stdint.h>
#include <stdbool.h>

#define F_CPU           16000000UL
#define SCL_CLOCK       100000UL   /* 100 kHz Standard Mode SCL */
#define SLAVE_ADDR_0X50 0x50       /* Target 7-bit Device Address */

/* TWI Status Mask Definition */
#define TWI_STATUS      (TWSR & 0xF8)

/**
 * @brief Initialize TWI hardware for 100 kHz Master operation at 16 MHz CPU.
 */
void TWI_Init(void) {
    /* SCL freq = F_CPU / (16 + 2 * TWBR * Prescaler)
       TWBR = ((16MHz / 100kHz) - 16) / (2 * 1) = 72 */
    TWBR = 72;
    TWSR = 0x00; /* Prescaler = 1 (TWPS1:0 = 00) */

    /* Enable TWI interface */
    TWCR = (1 << TWEN);
}

/**
 * @brief Transmit START condition and verify bus acquisition.
 * @return true on success (0x08 or 0x10), false on error.
 */
bool TWI_Start(void) {
    /* Clear TWINT, assert TWSTA (START), enable TWEN */
    TWCR = (1 << TWINT) | (1 << TWSTA) | (1 << TWEN);

    /* Wait for TWINT flag to set (transmission complete) */
    while (!(TWCR & (1 << TWINT)));

    /* Check status: 0x08 (START) or 0x10 (Repeated START) */
    uint8_t status = TWI_STATUS;
    return (status == 0x08 || status == 0x10);
}

/**
 * @brief Transmit STOP condition to release the bus.
 */
void TWI_Stop(void) {
    /* Assert TWSTO and clear TWINT to generate STOP */
    TWCR = (1 << TWINT) | (1 << TWSTO) | (1 << TWEN);

    /* Wait for hardware to clear TWSTO bit once STOP completes */
    while (TWCR & (1 << TWSTO));
}

/**
 * @brief Transmit a single byte (Address or Data) over TWI.
 * @param data Byte to transmit.
 * @return true if ACK received (0x18, 0x28, 0x40), false if NACK/Error.
 */
bool TWI_Write(uint8_t data) {
    /* Load byte into data register */
    TWDR = data;

    /* Clear TWINT and enable TWI to begin transmission */
    TWCR = (1 << TWINT) | (1 << TWEN);

    /* Wait for transmission to complete */
    while (!(TWCR & (1 << TWINT)));

    /* Verify ACK status (0x18 = SLA+W ACK, 0x28 = Data Byte ACK) */
    uint8_t status = TWI_STATUS;
    return (status == 0x18 || status == 0x28);
}

/**
 * @brief Write a single byte to an internal register of slave at 0x50.
 * @param reg_addr Target peripheral memory/register address.
 * @param val Data byte to write.
 * @return true on transaction success, false on communication failure.
 */
bool TWI_WriteByteToSlave(uint8_t reg_addr, uint8_t val) {
    /* 1. Transmit START */
    if (!TWI_Start()) {
        return false;
    }

    /* 2. Send 7-bit Slave Address (0x50) + Write Bit (0) => 0xA0 */
    uint8_t sla_w = (SLAVE_ADDR_0X50 << 1) | 0;
    if (!TWI_Write(sla_w)) {
        TWI_Stop();
        return false; /* NACK or device unresponsive */
    }

    /* 3. Send Internal Register / Memory Address */
    if (!TWI_Write(reg_addr)) {
        TWI_Stop();
        return false;
    }

    /* 4. Write Payload Data Byte */
    if (!TWI_Write(val)) {
        TWI_Stop();
        return false;
    }

    /* 5. Transmit STOP to release bus */
    TWI_Stop();
    return true;
}

3.1 The Tri-Register Model: DDRx, PORTx, PINx

Every AVR I/O pin is backed by three memory-mapped 8-bit registers that define its electrical state:

3.2 Transistor-Buffered High-Current LED Interfacing Derivations

An ATmega2560 pin can safely supply a maximum continuous DC current of $20\text{ mA}$ ($40\text{ mA}$ absolute maximum rating). When driving large loads or multiple LEDs ($I_C = 20\text{ mA}$), an NPN bipolar transistor (e.g., BC547, $\beta = 100$) is used as a low-side switch:

1. Base Resistor Calculation ($R_B$):
$$I_B = \frac{I_C}{\beta} = \frac{20\text{ mA}}{100} = 0.2\text{ mA}$$
// Apply overdrive saturation factor $k = 3$:
$$I_{B(\text{sat})} = 3 \times 0.2\text{ mA} = 0.6\text{ mA}$$
$$R_B = \frac{V_{OH} - V_{BE}}{I_{B(\text{sat})}} = \frac{5.0\text{ V} - 0.7\text{ V}}{0.6\text{ mA}} \approx 7.16\text{ k}\Omega$$
Standard Value Selected: $4.7\text{ k}\Omega$
2. Collector Resistor Calculation ($R_C$):
// Red LED $V_D = 1.8\text{ V}$, $V_{CE(\text{sat})} = 0.2\text{ V}$, $I_D = 10\text{ mA}$:
$$V_{RC} = V_{CC} - V_D - V_{CE(\text{sat})} = 5.0 - 1.8 - 0.2 = 3.0\text{ V}$$
$$R_C = \frac{V_{RC}}{I_{LED}} = \frac{3.0\text{ V}}{10\text{ mA}} = 300\,\Omega$$
Standard Value Selected: $330\,\Omega$

4.1 Timer vs. Counter Principles & Clock Routing

A Timer increments synchronously with clock pulses derived from the internal CPU oscillator ($f_{osc} = 16\text{ MHz}$) divided by a programmable prescaler (1, 8, 64, 256, 1024). A Counter increments on physical external transitions applied to a dedicated pin (e.g. pin T5 / PG4 for Timer 5).

4.2 16-Bit Timer Normal Mode Preload Derivations

$$\text{Timer Tick Period } T_{tick} = \frac{\text{Prescaler}}{f_{osc}}$$
$$\text{Ticks Required } N = \frac{T_{delay}}{T_{tick}} = \frac{T_{delay} \times f_{osc}}{\text{Prescaler}}$$
$$\text{Normal Mode 16-Bit Preload Value } = 65536 - N$$

Case Study 1: Generating 1.0 s Delay with Prescaler = 1024

$$N = \frac{1.0\text{ s} \times 16,000,000}{1024} = 15625\text{ ticks}$$ $$\text{Preload} = 65536 - 15625 = 49911 = \mathbf{0xC2F7}$$

Case Study 2: Generating 1.0 s Delay with Prescaler = 256

$$N = \frac{1.0\text{ s} \times 16,000,000}{256} = 62500\text{ ticks}$$ $$\text{Preload} = 65536 - 62500 = 3036 = \mathbf{0x0BDC}$$

4.3 Normal Mode vs. CTC (Clear Timer on Compare Match) Mode

In Normal Mode, the timer counts from Preload up to $0\text{xFFFF}$, sets the `TOV1` flag, rolls over to $0\text{x0000}$, and must be reloaded in software every cycle. In **CTC Mode (`WGM13:0 = 0100`)**, the hardware counter increments from $0\text{x0000}$ up to OCR1A and automatically resets to zero on match!

PWM MODES ATmega2560 • Hardware Waveform Generation

Pulse Width Modulation (PWM)

Timers: 1, 3, 4, 5 (16-bit) • 0, 2 (8-bit)

Pulse Width Modulation (PWM) on the ATmega2560 enables generating high-frequency digital square waves with variable duty cycles entirely in hardware. By automatically toggling output compare pins (OCnx) upon timer counter comparisons, the CPU remains free to execute application code while driving power electronics, dimming LEDs, creating analog audio, or controlling positioning servos.

1. Fast PWM Mode (Single-Slope Operation)

Fast PWM provides a high-frequency, single-slope PWM waveform. The 16-bit counter register (TCNTn) counts strictly upward from BOTTOM (0x0000) to TOP (defined by fixed 8/9/10-bit maximums or variable registers like ICRn / OCRnA), and then instantly restarts from BOTTOM in the next timer clock cycle.

Fast PWM Timing Equations
Output Frequency:
$$f_{\text{PWM}} = \frac{f_{\text{osc}}}{N \cdot (1 + \text{TOP})}$$
Non-Inverting Duty Cycle:
$$\text{Duty Cycle} = \frac{\text{OCR}nx + 1}{\text{TOP} + 1}$$

Where $f_{\text{osc}}$ is the system clock (typically $16\,\text{MHz}$), $N$ represents the prescaler divider ($N \in \{1, 8, 64, 256, 1024\}$), and $\text{TOP}$ is the upper count bound. In non-inverting mode (COMnx1:0 = 10), the output pin clears to LOW on match and sets to HIGH at BOTTOM.

2. Phase-Correct PWM Mode (Dual-Slope Operation)

Phase-Correct PWM is based on dual-slope counter behavior. The counter continuously counts up from BOTTOM (0x0000) to TOP, and then immediately counts down from TOP back to BOTTOM. Because the pulses are centered symmetrically around the counter peak, phase distortion is eliminated, making this mode optimal for motor commutation and noise-sensitive inductive loads.

Phase-Correct PWM Timing Equations
Output Frequency:
$$f_{\text{PWM}} = \frac{f_{\text{osc}}}{2 \cdot N \cdot \text{TOP}}$$
Non-Inverting Duty Cycle:
$$\text{Duty Cycle} = \frac{\text{OCR}nx}{\text{TOP}}$$

Because the counter increments and decrements over two slopes, the resulting maximum frequency is exactly half that of Fast PWM for the same prescaler and $\text{TOP}$ value.

3. Waveform Generation Mode (WGM) Bit Settings for 16-Bit Timers

In the ATmega2560 16-bit timers (Timer1, Timer3, Timer4, and Timer5), the PWM operating mode is governed by four control bits spread across registers TCCRnA (WGMn1:0) and TCCRnB (WGMn3:2).

4. Example 1: LED Dimming via Fast PWM (Timer 1 • OC1A / Pin 11)

This implementation uses 8-bit Fast PWM (Mode 5) with prescaler $N = 64$ to smoothly breathe an LED connected to PB5 (OC1A / Arduino Mega Digital Pin 11).

Frequency Verification: $f_{\text{PWM}} = \frac{16\,\text{MHz}}{64 \times (1 + 255)} = \frac{16{,}000{,}000}{16{,}384} \approx 976.56\,\text{Hz}$ — well above human flicker fusion threshold. 
// ============================================================================
// ATmega2560 - Fast PWM LED Dimmer (Timer 1, Channel A / PB5 / Pin 11)
// Mode 5: Fast PWM 8-bit, Non-Inverting, Prescaler = 64 (~976.56 Hz)
// ============================================================================

#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>

int main(void) {
    // 1. Configure Port B Pin 5 (OC1A / Arduino Mega Pin 11) as Output
    DDRB |= (1 << DDB5);

    // 2. Configure TCCR1A
    //    - COM1A1:0 = 10 : Clear OC1A on Compare Match, set at BOTTOM (Non-Inverting)
    //    - WGM11:10 = 01 : Mode 5 Fast PWM 8-bit (lower 2 bits)
    TCCR1A = (1 << COM1A1) | (1 << WGM10);

    // 3. Configure TCCR1B
    //    - WGM13:12 = 01 : Mode 5 Fast PWM 8-bit (upper 2 bits)
    //    - CS12:10  = 011: Prescaler = 64 (16 MHz / 64 = 250 kHz timer clock)
    TCCR1B = (1 << WGM12) | (1 << CS11) | (1 << CS10);

    // 4. Initialize Duty Cycle to 0% (LED Off)
    OCR1A = 0;

    uint8_t duty = 0;
    int8_t step = 1;

    while (1) {
        OCR1A = duty;  // Update Output Compare Register (Double-buffered)

        duty += step;

        // Reverse direction at bounds to create a continuous breathing pulse
        if (duty == 255) {
            step = -1;
            _delay_ms(120); // Brief hold at peak brightness
        } else if (duty == 0) {
            step = 1;
            _delay_ms(250); // Brief hold in fully off state
        }

        _delay_ms(6); // Step delay for smooth transition
    }

    return 0;
}

5. Example 2: Servo Motor Control (50 Hz • 1.0–2.0 ms Pulse on OC1A)

Standard RC hobby servos require a $50\,\text{Hz}$ carrier signal ($20\,\text{ms}$ period) where the high-time pulse width encodes target angular shaft position:

Full Left (0°) 1.0 ms (2,000 ticks)
Neutral (90°) 1.5 ms (3,000 ticks)
Full Right (180°) 2.0 ms (4,000 ticks)
Derivation: Mode 14 (Fast PWM with ICR1 as TOP)

To achieve an exact $50\,\text{Hz}$ period without sacrificing compare register resolution, we use Mode 14 with ICR1 set as the variable $\text{TOP}$. Choosing prescaler $N = 8$:

$$f_{\text{timer}} = \frac{16\,\text{MHz}}{8} = 2\,\text{MHz} \implies t_{\text{tick}} = 0.5\,\mu\text{s}$$ $$\text{TOP} = \frac{f_{\text{osc}}}{N \cdot f_{\text{target}}} - 1 = \frac{16{,}000{,}000}{8 \cdot 50} - 1 = 39{,}999 \implies \text{ICR1} = 39999$$

Each microsecond corresponds to $2$ timer counts ($1\,\mu\text{s} / 0.5\,\mu\text{s} = 2$). Therefore: 1.0 ms = 1,000 × 2 = 2,000 counts • 1.5 ms = 1,500 × 2 = 3,000 counts • 2.0 ms = 2,000 × 2 = 4,000 counts 

// ============================================================================
// ATmega2560 - 50 Hz RC Servo Controller (Timer 1, Mode 14 via ICR1)
// Output Pin: PB5 (OC1A / Arduino Mega Digital Pin 11)
// ============================================================================

#define F_CPU 16000000UL
#include <avr/io.h>
#include <util/delay.h>

// Timer counts calculated for N = 8 prescaler (0.5 µs per tick)
#define SERVO_TOP_50HZ   39999U  // 20.0 ms period ((16MHz / (8 * 50Hz)) - 1)
#define SERVO_MIN_TICKS  2000U   // 1.0 ms pulse (0 degrees)
#define SERVO_MID_TICKS  3000U   // 1.5 ms pulse (90 degrees, center)
#define SERVO_MAX_TICKS  4000U   // 2.0 ms pulse (180 degrees)

void servo_init(void) {
    // 1. Set PB5 (OC1A / Pin 11) as digital output
    DDRB |= (1 << DDB5);

    // 2. Configure Timer 1 for Mode 14 (Fast PWM, TOP = ICR1)
    //    - COM1A1:0 = 10 : Non-inverting on OC1A
    //    - WGM11:10 = 10 : Mode 14 lower bits
    TCCR1A = (1 << COM1A1) | (1 << WGM11);

    // 3. Configure TCCR1B
    //    - WGM13:12 = 11 : Mode 14 upper bits
    //    - CS12:10  = 010: Prescaler = 8 (Timer increments every 0.5 µs)
    TCCR1B = (1 << WGM13) | (1 << WGM12) | (1 << CS11);

    // 4. Define Frame Period in ICR1 (TOP = 39,999 -> 20 ms / 50 Hz)
    ICR1 = SERVO_TOP_50HZ;

    // 5. Park servo at 90 degree neutral position initially
    OCR1A = SERVO_MID_TICKS;
}

int main(void) {
    servo_init();
    _delay_ms(1000); // Allow servo to reach mechanical center

    while (1) {
        // Sweep smoothly from 0 deg to 180 deg
        for (uint16_t pos = SERVO_MIN_TICKS; pos <= SERVO_MAX_TICKS; pos += 10) {
            OCR1A = pos;
            _delay_ms(12);
        }
        _delay_ms(400);

        // Sweep smoothly back from 180 deg to 0 deg
        for (uint16_t pos = SERVO_MAX_TICKS; pos >= SERVO_MIN_TICKS; pos -= 10) {
            OCR1A = pos;
            _delay_ms(12);
        }
        _delay_ms(400);
    }

    return 0;
}
CHAPTER 5

Analog-to-Digital Converter (ADC) Architecture

5.1 SAR Principles, Registers, & Prescaler Physics

The ATmega2560 includes a 16-channel, 10-bit Successive Approximation Register (SAR) ADC. The internal capacitive DAC requires an input clock frequency between $50\text{ kHz}$ and $200\text{ kHz}$ to sustain full 10-bit resolution.

$$\text{Given } f_{osc} = 16\text{ MHz}, \quad \text{Select Prescaler} = 128 \implies f_{ADC} = \frac{16\text{ MHz}}{128} = \mathbf{125\text{ kHz}} \quad (\in [50, 200]\text{ kHz})$$
Configured using bits `ADPS2:0 = 111` in register `ADCSRA`.

Register Breakdown:

  • `ADMUX`: `REFS1:0` select reference ($01 = AV_{CC}$, $10 = 1.1\text{ V}$ internal bandgap); `ADLAR` selects left-justification (when set, top 8 bits appear directly in `ADCH`); `MUX4:0` select lower 8 channels.
  • `ADCSRA`: `ADEN` (Enable), `ADSC` (Start conversion), `ADATE` (Auto-trigger), `ADIF` (Interrupt flag), `ADIE` (Interrupt enable), `ADPS2:0` (Prescaler).
  • `ADCSRB`: Bit `MUX5` (high bit to access channels ADC8–ADC15 on Port K) and `ADTS2:0` (Auto-trigger source selection).
  • `DIDR0` & `DIDR2`: Digital Input Disable registers. Writing `'1'` disconnects digital input buffers on analog pins to prevent static leakage power.

5.2 Polling vs. Interrupt-Driven Latency Analysis

Blocking Polling Method:
ADCSRA |= (1 << ADSC); while ((ADCSRA & (1 << ADIF)) == 0); // Stalls CPU for ~110 us adc_val = ADC;

CPU is frozen in busy-wait loop for 13 ADC clock cycles ($\approx 104\text{--}110\,\mu\text{s}$), completely unable to service other tasks.

Interrupt-Driven Method:
ISR(ADC_vect) { adc_val = ADC; // Read 10-bit result ADCSRA |= (1 << ADSC); // Re-trigger }

CPU executes background calculations freely; hardware asserts ISR only when result is ready ($\approx 16\,\mu\text{s}$ overhead).

CHAPTER 6

Interrupt Subsystems & Vector Handling

6.1 Hardware Interrupt Execution Cycle

  1. An internal peripheral event (Timer compare) or external pin event (`INT0`–`INT7`) asserts.
  2. The corresponding interrupt flag bit is latched into `TIFR`, `EIFR`, or `ADCSRA`.
  3. If the individual mask bit is enabled and Global Interrupt Flag ($I$-bit in `SREG`) is set, the CPU completes current instruction execution.
  4. The Program Counter (PC) is pushed onto the SRAM stack; Stack Pointer (SP) is decremented.
  5. The hardware automatically clears the $I$-bit in `SREG` to disable nested interrupts.
  6. The CPU branches to the fixed vector address in the Interrupt Vector Table.
  7. Executing RETI pops PC from stack and atomically re-enables the $I$-bit in `SREG`.

6.2 External Interrupt Sense Modes (EICRA / EICRB)

ISCn1 ISCn0 Interrupt Sense Mode Description
0 0 Low Level on INTn pin generates interrupt asynchronously.
0 1 Any logical change (toggle) on INTn generates interrupt asynchronously.
1 0 Falling edge on INTn pin generates interrupt.
1 1 Rising edge on INTn pin generates interrupt.

1. With the help of a block diagram describe the functions of different components of a PLA device.

[12 M]

A Programmable Logic Array (PLA) is a PLD capable of realizing multi-output Boolean functions directly in standard Sum of Products (SOP) form: $F_k = \sum P_i = \sum (\prod L_j)$. Unlike a ROM (fixed AND, programmable OR) or a PAL (programmable AND, fixed OR), a PLA provides programmable connections in BOTH the AND array and the OR array. This dual programmability allows arbitrary product terms to be shared among multiple outputs.

Inputs (X0..Xn-1) ➔ [Input Inverters] ➔ 2n true/comp lines ➔ [Programmable AND Array (2n x m)] ➔ m Product Terms (P0..Pm-1) ➔ [Programmable OR Array (m x k)] ➔ k Sum Terms ➔ [Polarity XOR & Tristate Drivers] ➔ Outputs (F0..Fk-1)

Detailed Component Breakdown:

  • Input Buffers/Inverters: Accepts $n$ input variables and produces $2n$ true ($X_i$) and inverted ($\overline{X_i}$) rails with high current drive capability to charge parasitic line capacitance.
  • Programmable AND Plane: An orthogonal grid of $2n$ vertical input rails intersecting $m$ horizontal product-term lines. At each cross-point, a programmable switch (fuse or floating gate) connects the literal to a multi-input wired-AND line. Generates $m$ product terms: $P_k = \prod \widetilde{X_i}$.
  • Programmable OR Plane: Intersects the $m$ horizontal product lines with $k$ vertical sum lines. Because connections are programmable, any product term can drive any OR gate, and product terms can be shared across multiple outputs.
  • Output Polarity XOR Stage: Programmable XOR gate on each output: $F_{out} = F_{OR} \oplus \text{PolarityBit}$. Setting the bit to '0' produces Active-HIGH; setting it to '1' inverts the output (Active-LOW), implementing De Morgan's reduction directly.

The FAMOS transistor is an n-channel MOSFET with a completely isolated polysilicon gate (**Floating Gate**) surrounded by high-grade $SiO_2$, positioned underneath a second **Control Gate**.

---------------- Top Interpoly Oxide (SiO2) ----------------
[ FLOATING GATE (Isolated Polysilicon) ] ➔ Stores trapped electrons
---------------- Gate Oxide (SiO2 ~ 100-300 Å) -------------
[ n+ Source ] [ p-Silicon Substrate ] [ n+ Drain ]
  • Programming Mechanism (Avalanche Hot-Electron Injection): Applying $V_{PP} \approx 12.5\text{--}21\text{ V}$ to the control gate and $V_D \approx 8\text{--}12\text{ V}$ to the drain creates avalanche breakdown. 3. Show with an example that a macrocell adds to the versatility of a configurable hardware.

use IEEE.numeric_std.all; -- Standard package for synthesis-compliant unsigned arithmetic

entity counter_4bit is
    port (
        clk   : in  std_logic;                     -- Master clock input
        rst   : in  std_logic;                     -- Asynchronous reset (active-high)
        en    : in  std_logic;                     -- Synchronous count enable
        count : out std_logic_vector(3 downto 0)  -- 4-bit output vector (0 to 15)
    );
end entity counter_4bit;

architecture rtl of counter_4bit is
    -- Internal unsigned register prevents reading from 'out' port (VHDL-93 compliance)
    signal count_reg : unsigned(3 downto 0);
begin
    -- Synchronous process with asynchronous reset in sensitivity list
    counter_process : process (clk, rst)
    begin
        if rst = '1' then
            -- Asynchronous branch: triggers immediately when rst changes to '1'
            count_reg <= (others => '0');
        elsif rising_edge(clk) then
            -- Synchronous branch: evaluated exclusively on clock rising edge
            if en = '1' then
                count_reg <= count_reg + 1; -- Wraps naturally from 1111 to 0000 (mod 16)
            end if;
        end if;
    end process counter_process;

    -- Type conversion from numeric_std unsigned to IEEE standard logic vector
    count <= std_logic_vector(count_reg);
end architecture rtl;

library IEEE;
use IEEE.std_logic_1164.all;

entity fsm_seq_101 is
    port (
        clk  : in  std_logic; -- System clock
        rst  : in  std_logic; -- Asynchronous reset (active-high)
        din  : in  std_logic; -- Synchronous serial bitstream
        dout : out std_logic  -- Moore output flag ('1' when sequence detected)
    );
end entity fsm_seq_101;

architecture rtl of fsm_seq_101 is
    -- Enumerated type definition for readable, tool-optimized state mapping
    type state_t is (S_RESET, S_GOT1, S_GOT10, S_GOT101);
    
    signal current_state, next_state : state_t;
begin
    -------------------------------------------------------------------------
    -- PROCESS 1: Synchronous State Register (Sequential Logic)
    -- Sensitivity list contains ONLY the clock and the asynchronous reset.
    -------------------------------------------------------------------------
    state_reg_proc : process (clk, rst)
    begin
        if rst = '1' then
            current_state <= S_RESET;
        elsif rising_edge(clk) then
            current_state <= next_state;
        end if;
    end process state_reg_proc;

    -------------------------------------------------------------------------
    -- PROCESS 2: Combinational Next-State Logic
    -- Sensitivity list MUST contain ALL evaluated inputs: current_state, din.
    -------------------------------------------------------------------------
    next_state_proc : process (current_state, din)
    begin
        -- Safe default assignment guarantees no accidental latch inference
        next_state <= current_state;

        case current_state is
            when S_RESET =>
                if din = '1' then
                    next_state <= S_GOT1;
                else
                    next_state <= S_RESET;
                end if;

            when S_GOT1 =>
                if din = '0' then
                    next_state <= S_GOT10;
                else
                    next_state <= S_GOT1; -- Sequence remains at initial '1'
                end if;

            when S_GOT10 =>
                if din = '1' then
                    next_state <= S_GOT101; -- "101" sequence achieved
                else
                    next_state <= S_RESET;  -- Pattern broken
                end if;

            when S_GOT101 =>
                -- Overlapping sequence evaluation
                if din = '0' then
                    next_state <= S_GOT10;  -- "1010" ends with suffix "10"
                else
                    next_state <= S_GOT1;   -- "1011" ends with suffix "1"
                end if;

            when others =>
                next_state <= S_RESET;
        end case;
    end process next_state_proc;

    -------------------------------------------------------------------------
    -- MOORE OUTPUT LOGIC (Concurrent)
    -- Moore property: Output depends SOLELY on current_state, never din!
    -------------------------------------------------------------------------
    dout <= '1' when current_state = S_GOT101 else '0';

end architecture rtl;

4 Process Block Mechanics & Sensitivity List Execution Engine

How the event-driven VHDL simulation kernel schedules evaluations, and how sensitivity lists dictate hardware synthesis.

Event-Driven Kernel & Delta Cycles (δ)

A VHDL process is an infinite execution loop that immediately suspends upon reaching its end. The sensitivity list functions as an implicit wait on <sensitivity_list> positioned at the very end of the process body.

Whenever a signal in the list experiences an event (a state change), the simulation kernel wakes the process. Statements execute sequentially from top to bottom, but signal assignments using <= do not update immediately; they schedule updates for the next delta cycle (δ)—an infinitesimally small simulation time step that models parallel physical propagation delay.

Simulation-Synthesis Discrepancy Hazard

Synthesis compilers ignore sensitivity lists for combinational logic: they inspect the Boolean transfer function of all read signals and synthesize pure combinational gates (LUTs).

However, event-driven simulators strictly obey the sensitivity list. If an input (such as din) is omitted from a combinational sensitivity list, the simulator will fail to re-evaluate the process when din toggles. This causes the RTL testbench to report false behavior that completely diverges from actual programmed silicon! (Use VHDL-2008 process(all) when supported to eliminate this risk).

Golden Rules for Process Sensitivity Lists in RTL Synthesis

1. Pure Combinational Processes

Must contain every signal read on the right-hand side of assignments, inside if/elsif tests, and inside case selector expressions. 

-- Correct: All inputs present
process (current_state, din) begin ... end process;
-- VHDL-2008 equivalent:
process (all) begin ... end process;

Latch Warning: Every output must be explicitly assigned across all execution branches. An omitted branch forces the synthesizer to infer a level-sensitive latch (LD) to preserve previous state.

2. Clocked / Sequential Processes

Must contain ONLY the clock and optional asynchronous control signals (e.g., clk, rst). 

-- Correct: Only clock & async reset
process (clk, rst) begin ... end process;

-- WRONG: NEVER put enable or data inputs in clocked process list!
process (clk, rst, en, din) -- Anti-pattern!

Synchronous signals like en or data inputs must be gated inside elsif rising_edge(clk), ensuring they are only sampled at the active clock boundary.
